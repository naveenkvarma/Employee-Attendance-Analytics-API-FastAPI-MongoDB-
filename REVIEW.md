# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33-37) | `minutes if minutes > 10 else 0` compares truncated floor minutes. At 09:40:01 with shift 09:30 (elapsed 601s), `int(601/60)` is 10; `10 > 10` evaluates to False and returns 0. R2 requires strict grace period of 10:00 (>600s), giving 10. | Punch in at 09:40:01 for a 09:30 shift. Starter returns `0`, but contract requires `10`. | Truncate to whole seconds. Check if `(punch_in - start).total_seconds() > 600`. If so, return `int(total_seconds // 60)`, else `0`. |
| 2 | `compute_late_minutes` (lines 33-37) | Assumes naive datetimes and replaces hour/minute directly on `punch_in` without timezone handling or accounting for overnight shifts where punch-in before shift end belongs to previous day's shift. | Pass UTC or timezone-aware punch times; shifts crossing midnight produce incorrect shift start dates and negative minutes. | Truncate instant to seconds, convert to IST, calculate shift start on correct attendance date (R1). |
| 3 | `compute_work_hours` (lines 40-41) | Uses Python's built-in `round(..., 2)` which performs banker's rounding (round-half-to-even) instead of round-half-up (R4). | Duration of 2.125 hours (7650s): `round(7650/3600, 2)` gives `2.12` instead of `2.13`. | Use `Decimal(diff_sec) / Decimal(3600)` with `quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)`. |
| 4 | `compute_overtime` (lines 44-47) | Does not enforce the 30-minute minimum threshold (R3). Any punch-out past shift end (even 1 minute) is returned as overtime. | Punch out 5 minutes after shift end. Starter returns `5` instead of `0`. | Return `minutes if minutes >= 30 else 0`. |
| 5 | `compute_overtime` (lines 44-47) | For overnight shifts (`shift_end <= shift_start`), `shift_end` is on the next calendar day (`date + 1 day`). Starter sets `shift_end` on the same calendar date, placing it before shift start. | Overnight shift 22:00-06:00 on 2026-07-06 with punch out 06:40 on 2026-07-07 computes ~1480 min overtime instead of 40. | Check if overnight shift (`shift_end <= shift_start`); if so, add 1 day to `shift_end` calendar date. |
| 6 | Database startup (lines 22-24) | No indexes are created at startup. No unique constraint on `employees.emp_code` or `attendance_logs(emp_code, date)`, leading to duplicates and full collection scans (`COLLSCAN`). | Concurrently insert duplicate records or inspect `/admin/explain` queries; plans show `COLLSCAN`. | Create all required unique and compound query indexes idempotently at app startup. |
| 7 | `health` (lines 72-74) | Returns `{"status": "ok"}` statically without verifying MongoDB connectivity. Contract requires 200 only when MongoDB answers, else 503. | Stop MongoDB service; `GET /health` still returns 200 instead of 503. | Execute `client.admin.command('ping')` in a `try...except` block; raise `HTTPException(503, "Database unavailable")` on failure. |
| 8 | `create_employee` (lines 77-85) | Check-then-insert race condition (`find_one` followed by `insert_one`); concurrent requests with the same `emp_code` can both insert. | Send parallel POST requests with identical `emp_code`. Both succeed instead of exactly one 201 and one 409. | Rely on database unique index on `emp_code`; catch `DuplicateKeyError` and raise HTTP 409. |
| 9 | `create_employee` (lines 77-85) | Does not validate that `shift_start != shift_end` (OpenAPI requirement: `shift_start must differ from shift_end`, returning 422). | POST `/employees` with `shift_start: "09:00", shift_end: "09:00"` returns 201 instead of 422. | Add Pydantic model validator verifying `shift_start != shift_end`, raising 422 if equal. |
| 10 | `create_employee` (lines 77-85) | Sets `created_at` to `datetime.now()` (naive local time) and returns it unformatted. OpenAPI contract requires `created_at` as epoch milliseconds integer. | Inspect response; `created_at` is an ISO datetime string or Python object instead of epoch milliseconds. | Store UTC datetime in MongoDB and serialize `created_at` as integer epoch milliseconds in response. |
| 11 | `list_employees` (lines 88-96) | Incorrect pagination skip: `skip = page * page_size`. For `page=1, page_size=20`, skips 20 items, missing the entire first page! | Query `GET /employees?page=1` on a database with 10 employees; returns an empty list. | Set `skip = (page - 1) * page_size`. |
| 12 | `list_employees` (lines 88-96) | `total` uses `count_documents({})`, ignoring the `department` filter (R10 requires `total` to reflect applied filters). Also missing sort by `emp_code` ascending. | Query `GET /employees?department=Sales`; `total` returns total headcount of all departments combined. | Pass filter `q` to `count_documents(q)` and add `.sort("emp_code", 1)` to the query cursor. |
| 13 | `punch_in` (lines 99-122) | Concurrency race condition: uses check-then-insert (`find_one` then `insert_one`). Two concurrent requests for the same employee and date both insert. | Send two concurrent punch-in requests for the same date; both succeed with 201. | Enforce unique compound index on `("emp_code", "date")`; catch `DuplicateKeyError` and raise HTTP 409. |
| 14 | `punch_in` (lines 99-122) | Missing employee existence check. If employee does not exist, `emp["shift_start"]` raises `TypeError: 'NoneType' object is not subscriptable` resulting in 500 error instead of 404. | POST `/attendance/punch-in` with `emp_code: "EMP9999"` returns 500 Internal Server Error. | Check `if not emp: raise HTTPException(404, "Employee not found")`. |
| 15 | `punch_in` (lines 99-122) | Computes attendance date using local system timezone `datetime.fromtimestamp(...)` and `ts.date().isoformat()`, ignoring IST timezone and overnight shifts (R1). | Punch in at 05:00 IST on July 7 for a 22:00-06:00 shift. Assigned date is `2026-07-07` instead of `2026-07-06`. | Convert instant to IST; if overnight shift and time < `shift_end`, assign previous calendar day. |
| 16 | `punch_in` and `list_attendance` | Adds `doc["id"] = str(res.inserted_id)` and `d["id"] = str(d.pop("_id"))`. OpenAPI and DATA_MODEL state `_id` is internal and records have no `id` field. | Validating responses against OpenAPI schema fails due to unexpected `id` property. | Exclude `_id` and do not inject any `id` field into responses. |
| 17 | `list_attendance` (lines 124-150) | In-memory load: `docs = list(db.attendance_logs.find(q))` loads all records into Python memory and sorts via `docs.sort(...)`. Fails at 100k scale and lacks secondary sort `emp_code` ascending. | Memory spikes and latency on 100k records; records with matching dates are not ordered by `emp_code`. | Push sorting and pagination to database: `.sort([("date", -1), ("emp_code", 1)]).skip(skip).limit(page_size)` and `count_documents(q)`. |
| 18 | `list_attendance` (lines 124-150) | Missing date range validation. OpenAPI states `date_from > date_to -> 422`. Starter executes query returning empty list. | `GET /attendance?date_from=2026-07-10&date_to=2026-07-01` returns 200 instead of 422. | Add validation `if date_from and date_to and date_from > date_to: raise HTTPException(422, ...)`. |

Also note anything you looked at and decided was **not** a defect, and why:
- **Use of synchronous PyMongo client in FastAPI endpoints**: FastAPI executes standard `def` endpoint functions inside external thread pools (`anyio.to_thread.run_sync`), preventing event loop blockage while maintaining full concurrency across requests.
- **Pydantic model usage for request payloads**: The Pydantic model structure itself is appropriate, but required field validators, regex constraints, and value range checks matching `openapi.yaml`.
- **Storing dates and shift times as strings in MongoDB**: Storing `date`, `joined_on`, `shift_start`, and `shift_end` as `YYYY-MM-DD` and `HH:MM` strings is intentional as specified in `DATA_MODEL.md` to prevent unintended timezone offsets.
